# A12 — Learning‑based search (RL / diffusion / LLM code evolution)

**Priority: exploratory. Highest variance, no public precedent, cheap to pilot.**

## Why consider it at all

Every published record was found by hand‑tuned stochastic search. Machine
learning has *not* been tried here, and there is a specific reason to think it
could help: the expensive decision is not "where to put a square" but **which
squares to kick and in what order** — a policy‑shaped question. AlphaEvolve's
one packing success (hexagons) came from discovering a *structural* move
(unequal tilts) rather than from more iterations.

Three concrete, low‑risk pilots, in order of expected value per hour:

### 12.1 Learned improvement operator (learned LNS)
Train a small model to predict, for a stalled layout, **which `k` squares to
remove** so that refilling (A05) + quench (A06) yields the largest `L`
decrease. Labels are cheap: run the ruin‑and‑recreate with random subsets and
record the gain. Features: per‑square clearance, penetration contribution,
degree in the contact graph, distance to the seam, `n mod` grid structure.

Model: gradient‑boosted trees (`sklearn`) or a 2‑layer GNN. Data: generated by
A07 runs we are doing anyway.

### 12.2 Surrogate basin ranking
Instead of quenching every candidate (expensive), train a regressor
`E_final ≈ f(layout features)` on completed quenches, and only fully quench the
top `q %`. Classic "learned early stopping"; 3–10× throughput if the correlation
is decent.

### 12.3 LLM code evolution over *constructions*
An AlphaEvolve‑style loop where the program being evolved is a **construction
generator** (A03): the LLM proposes new pattern grammars, we evaluate the
resulting `L(n)` curve on a validation band (`n = 500…700`), and keep the best.
Objective is the actual competition score, so it cannot be gamed.

This is the one place where an LLM could plausibly beat the public notebooks,
because the public work has *no* automated search over constructions.

### 12.4 (Lower priority) RL placement policy
A pointer/GNN policy that sequentially places squares inside a fixed box,
trained with REINFORCE on `−penetration`. Published results in this family are
all for strip/bin packing; for a *square container with free rotation* the
action space is continuous and the reward is sparse. High risk, high cost.

### 12.5 (Lower priority) Diffusion / generative initialisation
A discrete diffusion model (DIFUSCO‑style) over "which cell/angle each square
takes" to produce diverse initial layouts, then A06/A08. Speculative.

## Expected gain

* 12.1: `1e-3…1e-2` if the learned subset selection is even 20 % better than
  random.
* 12.2: 2–5× effective compute (indirect; converts to whatever A07 yields).
* 12.3: unknown; could be `0` or `0.02`. Cheap to try (hours).
* 12.4/12.5: probably 0 within the available compute.

## Cost

* 12.1/12.2: medium (need generated data, but it comes free from A07 logs).
* 12.3: low per iteration; needs an LLM loop (this session can drive it).
* 12.4/12.5: high; CPU‑only here, so training is slow.

## Risks

* Overfitting to the training `n` band; always validate on held‑out puzzles.
* RL on a 3000‑dimensional continuous action space with sparse reward is a
  research project, not a competition tactic.
* The LLM loop can produce plausible‑looking but invalid constructions — every
  candidate must pass A01.
